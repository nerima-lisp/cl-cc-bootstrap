# API Reference

## `cl-cc/bootstrap` (`src/package.lisp`, `src/symbols/package.lisp`)

Pre-interned bootstrap symbols. Most are used or defined by later-loaded
compiler packages such as `cl-cc/compile`, `cl-cc/parse`, and `cl-cc/vm`; this
package interns their shared names first. The two helper names below are
generated by parse; their host implementations are installed by the `cl-cc-vm`
bridge.

- `rt-plist-put` — the generated call name for non-destructive plist updates;
  the VM implementation replaces an existing indicator rather than duplicating it.
- `rt-slot-set` — the generated call name for setting a CLOS slot by name and
  returning the value set.
- `our-eval`, `our-load`, `run-string-repl` — defined in `cl-cc/compile`;
  referenced here so `cl-cc/expand` can see them before `cl-cc/compile` loads.
- `*vm-runtime-callable-installer*`, `*runtime-vm-callable-register-hook*`,
  `*runtime-package-registry-provider*`, `*runtime-find-package-fn*`,
  `*runtime-intern-fn*`, `*runtime-set-symbol-value-fn*`,
  `*vm-eval-hook-installer*`, `*vm-macroexpand-hook-installer*`, and
  `*vm-parse-forms-hook-installer*` — VM/runtime installation hooks.
- `binop`, `const`, `var`, `cmp`, `integer-type`, `boolean-type`,
  `env-lookup` — pattern symbols the optimizer uses to match operators,
  values, types, and environment lookups.
- `make-cst-token`, `lexer-token-p`, `lexer-token-type`,
  `lexer-token-value` — the concrete syntax tree (CST) token bridge, defined
  in `cl-cc/parse`.
- `backquote`, `unquote`, `unquote-splicing` — quasiquote reader symbols
  shared between `cl-cc/parse` and `cl-cc`.

### Registry helpers re-exported by `cl-cc/bootstrap`

For compatibility, `cl-cc/bootstrap` also re-exports these symbols from
`cl-cc/bootstrap/backend-protocol`:

- `register-backend-bridge-provider thunk` registers a source of VM host-bridge
  entries; `backend-bridge-providers` collects the entries those providers
  return.
- `register-backend-vm-integration-installer thunk` registers an installer;
  `backend-vm-integration-installers` returns the registered installer thunks.
- `register-backend-global-seeder function` registers a VM-state seeder;
  `backend-global-seeders` returns the registered seeder functions.
- `register-backend-parser language function` replaces the parser for a
  language; `find-backend-parser language` returns it or `nil`.
- `register-backend-input-validator language function` replaces the validator
  for a language. It receives the parser's top-level forms and signals an error
  to reject them; its return value is ignored.
  `find-backend-input-validator language` returns the validator or `nil`.

## `cl-cc/backend-protocol` (`src/backend-protocol/`)

### Registry

- `*registered-backends*` — alist of `(language . backend)`, most recently
  registered first.
- `register-backend language backend` — register `backend` under `language`,
  replacing any previous registration.
- `call-with-backend-registration language backend registered replaced` —
  continuation-passing style (CPS) dispatch: call `registered` with `backend`
  if no backend was registered before, or `replaced` with `backend` and the
  previous backend otherwise. Return whichever callback returns.
- `call-with-registered-backend language found not-found` — dispatch on
  presence: call `found` with the backend if `language` is registered, else
  call `not-found` with no arguments. Return whichever callback returns.
- `registered-backend language` — return the backend registered under
  `language`, or `nil`.

In these operations, a continuation is a callback the function invokes for an
outcome. The update in `call-with-backend-registration` happens before either
callback runs.

### Backend hooks

- `backend-bridge-symbols backend` — the fbound symbols `backend` wants
  callable from compiled code. Defaults to `()`.
- `backend-global-symbols backend` — the bound special variables `backend`
  wants seeded into VM globals. Defaults to `()`.
- `install-backend-vm-integration backend integration` — give `backend` the
  VM capabilities in `integration`. Defaults to a no-op.

### VM integration

- `vm-integration` / `make-vm-integration` / `vm-integration-p` — a struct of
  six capability closures (`closure-p`, `call-closure`, `global-bound-p`,
  `global-value`, `set-global`, `remove-global`), each defaulting to a
  closure returning `nil`.
- `vm-integration-closure-p`, `vm-integration-call-closure`,
  `vm-integration-global-bound-p`, `vm-integration-global-value`,
  `vm-integration-set-global`, `vm-integration-remove-global` — the six slot
  accessors.
